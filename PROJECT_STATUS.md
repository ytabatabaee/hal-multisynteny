## 2026-11-10 — checkpoint visualization

The follow-up viewer implementation normalizes authoritative checkpoint tables
and renders parent atoms/blocks, left/right edge evidence, occurrences,
downward blocks, and propagated boundaries in a self-contained HTML page.
Controls use DOM listeners rather than inline handlers; half-open region
filtering is deterministic, and `--max-blocks` counts every rendered evidence
type. The committed example is generated through `visualize-run` from a small
synthetic checkpoint.

Visualization tests pass and Ruff is clean. The viewer displays recorded
evidence only; it does not establish biological absence, orthology, or copy
identity. The isolated `python -m build` command remains environment-blocked
when Hatchling cannot be downloaded.

The hardening pass (commit `8a396f8`) makes the HTML a truthful bounded
preview: the payload records its embedded chromosome/interval, all edits stay
inside that extent, downward blocks are not duplicated, and the object limit
counts atoms, blocks, mappings, occurrences, downward blocks, and boundaries.
Dynamic checkpoint text is created with DOM APIs/textContent; no data-derived
inline handlers or innerHTML remain. The synthetic example was regenerated by:

```bash
hal-multisynteny visualize-run --run-dir tests/fixtures/visualization --node root \
  --chrom chr1 --start 0 --end 260 --output docs/examples/visualization.html
```

Final validation: `PYTHONPATH=src .venv/bin/python -m pytest -q` → 251 passed,
10 optional HAL tests skipped; `ruff check .` → clean. `python -m build` was
attempted but could not download isolated Hatchling dependencies. No
reconciliation, classification, merging, or HAL mapping behavior changed.

The latest corrective pass extends the committed fixture with direct-child
mapping statuses, node/leaf occurrences, merge/conflict evidence, downward
lineage, and propagated boundaries. The region summary is now bounded to the
embedded interval, and boundary points use half-open left-inclusive/right-
exclusive selection. Six focused visualization tests pass in addition to the
full-suite baseline; display joins remain read-only and do not rewrite any
checkpoint evidence.

## 2026-11-10 — native-segment chaining milestone

Added the selectable `segment-chaining` reconciliation policy. It reuses the
existing atomic sweep/merge decisions while relaxing only source block-ID
identity; collinearity, orientation, chromosome, copy, status, and child
support barriers remain enforced. `AtomicInterval.final_parent_block_id`
preserves atom-to-final-block correspondence, and the legacy
`common-refinement` policy remains the default.

The `hal-native-segments` backend and `--leaf-init native` now run directly on
the tiny real HAL through native `halAlignedExtract --viewParentCoords`, with
one batched process per direct edge and no halSynteny, leaf-block, or mapping
table input required. The environment lacks HAL C++ headers, but the installed
native CLI provides the needed segment stream; no standalone helper is needed.
The same backend accepts an explicit segment table for deterministic tests.
Existing backend outputs are unchanged; this remains experimental biological
validation.

On the four-leaf tiny HAL, the complete native run (automatic leaf
initialization, bottom-up reconciliation, and downward refinement) completed
in 1.35 s wall / 0.83 s user / 0.38 s system; the root contained 4 atomic and
4 final blocks with 40 supported bases. Peak-memory reporting was unavailable
because macOS `time -l` could not query `kern.clockrate`.

The hardening follow-up changed native extraction to line-streaming with a
child-chromosome interval index (`O(S log S + B log B + K)` target) and a
run-scoped cache shared by leaf initialization and edge extraction. Native HAL
does not encode orthology/paralogy/copy identity; single segments are therefore
coordinate-unique but biologically unresolved, while distinct target geometries
for one child block are retained as ambiguous alternatives. This prevents the
adapter from inventing copy IDs or silently collapsing duplications.

Final validation with `.hal-env/bin` on `PATH`: 266 tests passed and 1 warning;
Ruff passed. The existing portable-evidence regression also passed. Package
build remains network-blocked while isolated Hatchling dependencies are fetched.

The CI follow-up found that `results-all-direct/plan.json` is ignored and exists
only in some local workspaces. Including it alone made
`planned_edges_without_psl` environment-dependent. Report generation now starts
from the tracked canonical `audit/plan.json` and deduplicates optional generated
plans. The portable report regression passes without ignored files.

The hardened tiny-HAL benchmark is recorded in
`experiments/native-segments/REPORT.md`: six direct edges caused six native
invocations and 10 extracted segment rows, and resumed execution reused all
cache entries. The pilot still has no accepted root merges, so larger-block
biological validation remains outstanding.

## 2026-11-10 — controlled native chaining validation

Added `tests/fixtures/native_chaining_hal/`, a reproducible real HAL built from
committed MAFs with four leaves, a conserved multi-segment region, an A-lineage
inversion, and a D `chrD2` translocation. Independent expected relationships
are recorded in `expected-results.json`. The native run produced an actual
Anc1 merge (4 atomic intervals to 3 blocks), chained Anc2 to 2 blocks while
respecting the chromosome barrier, and retained three Root blocks at exact
coordinates 0–40, 40–60, and 60–80. Downward refinement completed with length
and interval conservation for all leaves.

Inherited descendant-classification barriers from Anc1 make the Root decision
use both child subtrees and reject joins across its 40–60 rearrangement. The
same HAL with halSynteny initialization provides a common-refinement control and
has matching Root coordinates but no accepted segment merges. This does not
validate native paralogy; copy identity remains unresolved by the HAL CLI.
Details are in `experiments/native-chaining-validation/REPORT.md`.

Gap and duplication regressions now make the remaining semantics explicit:
current segment chaining rejects even a short non-adjacent gap because exact
child adjacency is required, while repeated native target geometries remain
ambiguous with unresolved copy identity. Gap-tolerant chaining and native
paralogy extraction are not yet implemented.
Implemented persistent native segment-index infrastructure in
`src/hal_multisynteny/native_index.py` and
`scripts/build_native_segment_index.py`. It streams one direct edge into an
atomic SQLite database with child/parent coordinate indexes, identity metadata,
deterministic overlap queries, and interrupted-build cleanup. The Palaeognathae
comparison remains pending because building the two large direct-edge indexes
is still an expensive one-time scan; no partial extraction is treated as
complete evidence.

45,331,345 native rows (about 6.6 and 6.7 GiB), with the HAL checksum and

The indexed native Method 3 run completed in 86.03 s and its split-only
downward checkpoint passed conservation checks. It emitted 10 Anc3 blocks / 107
covered bases: five `shared_consistent` and five `right_only`, with zero
ambiguity, duplication, orientation, or order conflicts. This is an
engineering pilot on two leaves, not a biological conclusion.

The identical Method 1 command using `halSynteny` was attempted for 313.53 s
and interrupted while initializing the first leaf; no checkpoint was produced.
Because this `halSynteny` invocation has no region restriction, the remaining
blocker is a bounded Method 1 leaf-initialisation path (or precomputed valid
leaf checkpoints) on the same fixed region. The exact commands and traceback
context are in `experiments/palaeognathae-native-comparison/REPORT.md`.
