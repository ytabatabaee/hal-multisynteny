## 2026-11-10 — checkpoint visualization

The follow-up viewer implementation normalizes authoritative checkpoint tables
and renders parent atoms/blocks, left/right edge evidence, occurrences,
downward blocks, and propagated boundaries in a self-contained HTML page.
Controls use DOM listeners rather than inline handlers; half-open region
filtering is deterministic, and `--max-blocks` counts every rendered evidence
type. The committed example is generated through `visualize-run` from a small
synthetic checkpoint.

Visualization tests pass and Ruff is clean. The viewer displays recorded
evidence only; it does not establish biological absence, orthology, or copy
identity. The isolated `python -m build` command remains environment-blocked
when Hatchling cannot be downloaded.

The hardening pass (commit `8a396f8`) makes the HTML a truthful bounded
preview: the payload records its embedded chromosome/interval, all edits stay
inside that extent, downward blocks are not duplicated, and the object limit
counts atoms, blocks, mappings, occurrences, downward blocks, and boundaries.
Dynamic checkpoint text is created with DOM APIs/textContent; no data-derived
inline handlers or innerHTML remain. The synthetic example was regenerated by:

```bash
hal-multisynteny visualize-run --run-dir tests/fixtures/visualization --node root \
  --chrom chr1 --start 0 --end 260 --output docs/examples/visualization.html
```

Final validation: `PYTHONPATH=src .venv/bin/python -m pytest -q` → 251 passed,
10 optional HAL tests skipped; `ruff check .` → clean. `python -m build` was
attempted but could not download isolated Hatchling dependencies. No
reconciliation, classification, merging, or HAL mapping behavior changed.

The latest corrective pass extends the committed fixture with direct-child
mapping statuses, node/leaf occurrences, merge/conflict evidence, downward
lineage, and propagated boundaries. The region summary is now bounded to the
embedded interval, and boundary points use half-open left-inclusive/right-
exclusive selection. Six focused visualization tests pass in addition to the
full-suite baseline; display joins remain read-only and do not rewrite any
checkpoint evidence.

## 2026-11-10 — native-segment chaining milestone

Added the selectable `segment-chaining` reconciliation policy. It reuses the
existing atomic sweep/merge decisions while relaxing only source block-ID
identity; collinearity, orientation, chromosome, copy, status, and child
support barriers remain enforced. `AtomicInterval.final_parent_block_id`
preserves atom-to-final-block correspondence, and the legacy
`common-refinement` policy remains the default.

The `hal-native-segments` backend and `--leaf-init native` now run directly on
the tiny real HAL through native `halAlignedExtract --viewParentCoords`, with
one batched process per direct edge and no halSynteny, leaf-block, or mapping
table input required. The environment lacks HAL C++ headers, but the installed
native CLI provides the needed segment stream; no standalone helper is needed.
The same backend accepts an explicit segment table for deterministic tests.
Existing backend outputs are unchanged; this remains experimental biological
validation.

On the four-leaf tiny HAL, the complete native run (automatic leaf
initialization, bottom-up reconciliation, and downward refinement) completed
in 1.35 s wall / 0.83 s user / 0.38 s system; the root contained 4 atomic and
4 final blocks with 40 supported bases. Peak-memory reporting was unavailable
because macOS `time -l` could not query `kern.clockrate`.

The hardening follow-up changed native extraction to line-streaming with a
child-chromosome interval index (`O(S log S + B log B + K)` target) and a
run-scoped cache shared by leaf initialization and edge extraction. Native HAL
does not encode orthology/paralogy/copy identity; single segments are therefore
coordinate-unique but biologically unresolved, while distinct target geometries
for one child block are retained as ambiguous alternatives. This prevents the
adapter from inventing copy IDs or silently collapsing duplications.

Final validation with `.hal-env/bin` on `PATH`: 266 tests passed and 1 warning;
Ruff passed. The existing portable-evidence regression also passed. Package
build remains network-blocked while isolated Hatchling dependencies are fetched.

The CI follow-up found that `results-all-direct/plan.json` is ignored and exists
only in some local workspaces. Including it alone made
`planned_edges_without_psl` environment-dependent. Report generation now starts
from the tracked canonical `audit/plan.json` and deduplicates optional generated
plans. The portable report regression passes without ignored files.

The hardened tiny-HAL benchmark is recorded in
`experiments/native-segments/REPORT.md`: six direct edges caused six native
invocations and 10 extracted segment rows, and resumed execution reused all
cache entries. The pilot still has no accepted root merges, so larger-block
biological validation remains outstanding.

## 2026-11-10 — controlled native chaining validation

Added `tests/fixtures/native_chaining_hal/`, a reproducible real HAL built from
committed MAFs with four leaves, a conserved multi-segment region, an A-lineage
inversion, and a D `chrD2` translocation. Independent expected relationships
are recorded in `expected-results.json`. The native run produced an actual
Anc1 merge (4 atomic intervals to 3 blocks), chained Anc2 to 2 blocks while
respecting the chromosome barrier, and retained three Root blocks at exact
coordinates 0–40, 40–60, and 60–80. Downward refinement completed with length
and interval conservation for all leaves.

Inherited descendant-classification barriers from Anc1 make the Root decision
use both child subtrees and reject joins across its 40–60 rearrangement. The
same HAL with halSynteny initialization provides a common-refinement control and
has matching Root coordinates but no accepted segment merges. This does not
validate native paralogy; copy identity remains unresolved by the HAL CLI.
Details are in `experiments/native-chaining-validation/REPORT.md`.

Gap and duplication regressions now make the remaining semantics explicit:
current segment chaining rejects even a short non-adjacent gap because exact
child adjacency is required, while repeated native target geometries remain
ambiguous with unresolved copy identity. Gap-tolerant chaining and native
paralogy extraction are not yet implemented.
Implemented persistent native segment-index infrastructure in
`src/hal_multisynteny/native_index.py` and
`scripts/build_native_segment_index.py`. It streams one direct edge into an
atomic SQLite database with child/parent coordinate indexes, identity metadata,
deterministic overlap queries, and interrupted-build cleanup. The Palaeognathae
comparison remains pending because building the two large direct-edge indexes
is still an expensive one-time scan; no partial extraction is treated as
complete evidence.

## 2026-11-11 — opt-in gap-tolerant native chaining

Added a selectable gap-tolerant continuation rule for Method 3. Strict
segment-chaining remains the default. With `--gap-tolerant`,
`--max-merge-gap` bounds the parent gap and `--max-child-gap` bounds the child
gap; all chromosome, orientation, order, copy, ambiguity, inherited-boundary,
filtered-atom, and tree-aware barriers remain active. Gapped blocks retain
separate exact aligned components and never fabricate mappings through the
unsupported gap.

On `PalaeognathaeAnc3refChr301:0-100000`, strict chaining produced 3,371
blocks (median 8 bp); thresholds 100/1,000/10,000 reduced this to 3,082/3,078/
3,074 blocks with 289/293/297 gap joins. Downward interval and covered-length
conservation remained exact in every run. These are engineering observations,
not genome-wide biological conclusions. Full details and commands are in
`experiments/gap-tolerant-chaining/REPORT.md`.

## 2026-11-11 — orientation-aware chaining correction

The native strand audit on the 100-kb Anc3 region found that all 2,564 prior
`orientation_conflict` atoms shared one stable `(-,+)` signature: the left
edge was uniformly reverse-oriented and the right edge uniformly forward-
oriented. Reconciliation now permits constant opposite orientations between
child tracks while retaining orientation transitions, chromosome changes,
non-monotonic order, ambiguity, and duplication as barriers. Native extraction
semantics were verified against direct `halAlignedExtract` coordinates and
independent `halLiftover` evidence; no extractor change was needed.

The revised strict run on `PalaeognathaeAnc3refChr301:0-100000` produced 1,553
blocks (median 22 bp, mean 64.4 bp) versus 3,371 blocks before the correction.
Revised gap-tolerant runs produced 1,025 blocks at 100-bp gaps and 1,014 at
1-kb gaps. Downward conservation remained exact. A revised 1-Mb attempt was
interrupted after 367.64 s in relationship accounting before checkpoint output;
this is recorded as a scaling blocker in
`experiments/orientation-aware-chaining/REPORT.md`.

## 2026-11-11 — VGP-scale optimization and completed 10-Mb benchmark

Removed several observed quadratic scans without changing reconstruction
semantics: relationship/provenance aggregates are computed once per
record/atom incidence; block occurrences and merge-decision reasons use direct
lookups; leaf propagation is indexed by child block/chromosome; and native leaf
overlap validation uses a per-chromosome running maximum end. Optional
`run-tree --profile --profile-output` records stage wall times and peak RSS.

The optimized 1-Mb runs completed in 167.95 s strict and 147.20 s gap-tolerant
(1-kb thresholds). The full 10-Mb strict and gap-tolerant runs also completed:
968.22 s / 9.68 GB RSS and 734.26 s / 9.62 GB RSS, respectively, with downward
covered-length and interval-union conservation true for Anc3 and both leaves.
The 10-Mb target of 120 s and 4 GB RSS was not met. Downward refinement and
checkpoint serialization dominate at this scale. Detailed tables and the VGP
architecture assessment are in `experiments/scalability-10mb/REPORT.md`.

## 2026-11-11 — compact ancestry mode

Added opt-in `--compact-ancestry` storage with immediate ancestry links,
streamed lazy descendant queries (`query-descendants`), and compact boundary
metadata. Legacy eager leaf materialization remains the default; compact mode
does not run the legacy downward materialization when `--downward-refinement`
is supplied. Reverse-strand projection, selected-leaf pruning, gap handling,
and exact equivalence with legacy leaf occurrences are covered by focused tests.

Using the indexed Palaeognathae HAL and the two-leaf Anc3 subtree, compact
100-kb/1-Mb/10-Mb runs completed in 93.14/116.00/325.33 s with peak RSS
61 MB/448 MB/3.35 GB. The 10-Mb checkpoint has 109,323 Anc3 blocks and 673,271
direct ancestry links, with zero eager internal leaf occurrences. Results and
commands are in `experiments/compact-ancestry-10mb/REPORT.md`. These are
engineering measurements, not genome-wide biological conclusions.

## 2026-11-11 — experimental anchor-chaining policy

Added opt-in `--reconciliation-policy anchor-chaining`; the default and prior
segment-chaining policies are unchanged. Anchor mode removes soft inherited/
classification boundaries when at least one child remains collinear, while
chromosome, orientation, order, unresolved-copy, and configured gap barriers
remain hard. On the indexed Anc3 interval, anchor gap-1kb reduced blocks from
1,014 to 415 at 100 kb, 18,396 to 5,554 at 1 Mb, and 84,009 to 35,338 at
10 Mb; empirical mean spans increased to 241.0, 180.1, and 283.0 bp. Exact
child-gap bases and structural-barrier counts remain reported separately.

This is an experimental two-leaf engineering result, not a biological claim.
The algorithm uses a linear ordered compatibility sweep rather than a full DP
over alternatives; the next step is independent-anchor validation and then a
score-bearing DP for competing chains. Details and exact profiles are in
`experiments/anchor-chaining/REPORT.md`.

## 2026-11-11 — Method 1/Method 3 fragmentation diagnosis

The installed HAL v2.2 `halSynteny` advertises `--queryChromosome` but no
ancestral interval restriction. A chromosome-bounded attempt on the first
Palaeognathae child edge ran for 194.69 s, produced a zero-byte PSL, and was
interrupted; the earlier whole-edge attempt ran 313.53 s before interruption.
No partial PSL was treated as a completed Method 1 chain result.

The complete 10-Mb Method 3 boundary audit found 109,322 rejected joins. The
primary reasons were classification/inherited barriers (83,302; 76.2%) and
non-monotonic child order (25,385; 23.2%); raw overlapping counts included
34,648 chromosome transitions, 34,628 orientation transitions, and
61,808/48,684 forward/reverse non-collinearity reasons. Revised 100-kb gap
thresholds saturated at 1,009 blocks by 10 kb; 50 kb added no further joins.

The diagnostic report, reusable scripts, compact tables, and SVG/PDF/PNG
figures are in `experiments/block-quality-comparison/`. Anura was not present
locally, so no cross-clade run was attempted. The recommended next step is a
bounded/precomputed halSynteny path, followed by controlled anchor-chaining
evaluation; production reconciliation semantics remain unchanged.

## 2026-11-11 — anchor-chaining validation

Independent `halLiftover --outPSLWithName` checks matched 12/12 sampled native
child components for exact parent/child coordinates and relative orientation.
The 10-Mb anchor output contains 15,189 blocks below 10 bp and 32,391 below
1 kb; 10,028 blocks span positive child gaps, which remain excluded from
aligned-base counts. Remaining boundaries are dominated by repeated child
chromosome/orientation transitions (34,639/34,628), while residual order
barriers number 89 and unresolved duplication/complex barriers 618.

The evidence does not justify a dense global DP over the current native stream:
hard structural transitions dominate. The next specific improvement is indexed
pre-atomic grouping of consecutive collinear native fragments, retaining all
alternatives before evaluating a score-based DP. Details, validation coordinates,
and figures are in `experiments/anchor-chaining-validation/`.
